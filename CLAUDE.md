# Nhậu Đêm 134: notes for Claude

A virtual sidewalk beer pub (quán nhậu vỉa hè) streamed on TikTok through TikTok LIVE Studio (Link source `http://lvh.me:3000/?view=stage`, 1080×1920). Reply in Vietnamese, short. The old cartoon version lives on branch `ban-cu-hoat-hinh`.

## Never break the live

- Only `?view=stage` makes sound. Check visuals with the dashboard preview (`?view=stage&preview=1`, silent) or the "Thử không cần live" buttons (`POST /api/demo`).
- Changes to `server.js`, `pub.js` or `tts.js` need a server restart; ask first if the owner may be live. Page code is never cached: refreshing the Link source picks it up.
- `index.html` loads only `stage.css` for the stage and only `dashboard.css` for the admin: their class names (`.side`, `.body`…) clash.

## How it works

- `server.js`: plain `node:http`. Settings (`settings.json`, includes the FPT.AI / Zalo AI keys; `publicSettings()` strips them before anything goes to a page), the gold board, the "cả quán dzô" wave (4 people typing the keyword in 15 s), gifts by coins each (treat > smash > hotpot > food; thresholds in settings). SSE `/api/events?role=stage|preview|dash`. Host/Origin checks keep other sites out. Viewers are keyed by TikTok `uniqueId`.
- `pub.js`: comment parsing (`seatWish`: "nhậu" → table 0, "bàn N" → N; `orderedItem` from `menu.js` aliases), the kitchen queue (gift orders first, 3 on the fire) and the list of who has a stool. A free dish needs a seat: no seat → `orderNote` `kind: 'seat'` and the host says "chat nhậu vào bàn trước". The seat list mirrors the stage (follow / "nhậu" / "bàn N" / gift give one, `seatIdleMin` of silence takes it back); `server.js` keeps it warm with `pub.touchSeat` on every comment. Chat events carry `kind` ('sit', 'table', 'order') so the stage doesn't read those aloud.
- `tts.js`: voices by id (`VOICES`): edge (msedge-tts), google, fpt (FPT.AI v5, async link polled), zalo. Always the chosen voice, never a fallback to another; a failing line is skipped. `POST /api/tts/test` reports the real error to the admin.
- Stage (`public/js/stage.js`): renders and speaks only. Art in `public/js/art/` (painted-style SVG, realistic proportions, no chibi). Positions are px in the 430×764 stage, scaled to the window with `transform: scale` (never CSS zoom: zoom re-lays out the scene every frame). `layout.js` has 8 tables in 3 rows (3+3+2), **6 seats each**: 2 behind facing out ('front'), 2 at the ends turned in ('side'), 2 in front with their backs to the camera ('back', drawn by `seatedSVG` with `headBack`) — the front pair sits off-centre so the table number stays readable. Depth scale `scaleAt(y)` per seat. Walkers (guests, cook, chạy bàn) move with rAF through `placeWalker`, which only writes `transform`; motorbikes animate `transform` too.
- Every seated viewer wears a name card over their head (`tagHTML`/`fillTag`): TikTok avatar (first letter if the picture fails) plus name, always on, hidden while a speech bubble is up. Regulars only get a card while the host talks to them.
- Seats only on follow / chat "nhậu" / order / gift / "bàn N"; idle `seatIdleMin` frees the seat (TikTok sends no leave event). Six NPC regulars (`NPC_SEATS`) keep the quán from looking empty and give their stool up to viewers; the other 42 stay for real people. The cook leaves the stove to serve each finished dish (`serve`), up to 2 waiters help when the queue grows.
- Lặt vặt (`menu.js`, `kind: 'item'`: đá, khăn lạnh, chén đũa, tăm giấy, chanh ớt, nước mắm): free, 3–5 s, served by a waiter, not cooked (the stove does not light for them), and they queue separately from food so a guest can ask for ice while their dish is on the fire. Their own lines are `orderLines.orderItem` / `itemDone`; the art is the `kind === 'item'` branch of `dishSVG`.
- Closing (`closing` / `opening` events): STREAM_END, a drop that lasts 25 s, or the owner pressing Ngắt kết nối / "Dọn quán" make `closeHall()` fire; the stage walks everyone out one by one, clears the tables, says goodbye, and brings the regulars back when a live starts again (or after 2 minutes). TikTok still sends no per-viewer leave event — that is what `seatIdleMin` is for.
- Sharpness: nothing full-screen may carry high-frequency noise or a blur filter. The 430×764 stage is scaled ~2.5× for 1080×1920, so a grain layer turns into mush and eats the live's bitrate (that was the old `finishSVG` grain, removed). Avoid `will-change: transform` on moving art for the same reason: it pins the raster scale.
- Never let the live freeze. Three watchdogs, all of them load-bearing: `api.js` rebuilds the SSE when no message (the server's `ping` every 15 s included) has arrived for 50 s — LIVE Studio's connection sometimes dies silently, and before this the quán just stopped dead; `walk()` has a `setTimeout` that lands the walker if rAF stops, so a stalled frame loop cannot deadlock `pumpServe` (`chefOut` stuck true = nothing is ever served again); `sound.guard()` keeps the voice alive. `tts.js` shares one synthesis per identical line (`inflight`), caps the Edge queue and retries twice, so a slow night cannot pile up minutes of work and leave the quán silent.
- Low mode: the stage measures its own frame rate and adds `.low` to the stage when it drops under ~26 fps twice in a row (CSS then stops the always-on animations: breathing, sign bulbs, glow, ticket sway; JS sends fewer motorbikes and less steam). It goes back to full only after 30 s of smooth frames, and after three flips it stays low. `window.__nd.setLow(true)` forces it.
- Voice (`public/js/sound.js`): lines are fetched from `/api/tts` as a blob **before** they are needed (`prefetch`/`warmNext`), so one line follows the next without a gap; all lines play through two reused `<audio>` elements (one wired into the filter chain once, one plain for when the AudioContext is asleep) — never a new element and filter graph per line. `guard()` runs every 0.9 s: it resumes a paused player, drops a line stuck for 4 s, restarts an idle queue, and a line the server fails twice is thrown away. The voice must never go silent for the rest of a live.
- Regulars (`public/js/npc.js`, setting `npcLife`, six of them): the server picks when a regular talks (`npc` event) or orders a free dish (`pub.npcOrder`, user id `npc-K`, never on the board); the stage shows it only if that regular still has their seat, and the host answers only when no viewer comment is waiting (`hostFree`). Never put words in a real viewer's mouth.
- Real answers to viewer questions: `public/js/answers.js` (time, date, address 134 Trần Phú, how to sit/order/change table, gift tiers, my table, my dish, top 1, arithmetic, "is this a bot" answered honestly). Unknown questions fall back to the bựa lines.
- Dzô: `public/js/cheers.js` draws two bia hơi glasses clinking (big one in the middle at most every 5 s, small ones over heads); the clink sound is `sound.dzo()` playing `assets/audio/dzo1..3.mp3` (made by `tools/tieng-dzo.py`).
- Voice lines: `lines.js`, `bua.js`, `order-lines.js`; comment topics in `chat.js` match accented words (no accent stripping: "thì" must not match "thi"). A new topic needs an entry in the `Topic` typedef, in `TOPICS`, and in **both** `BUA_REPLIES` (bua.js) and `REPLIES` (lines.js) — `npm run check` catches a missing one. `vo` (vợ/chồng gọi về) must stay before `lovelife`, which would otherwise swallow it. The pools worth growing when the quán feels repetitive: `BUA_ACK` (any comment), `TALK_NAMED` / `TALK_ROOM` (the host starting a conversation), `IDLE` and `NPC_TALK`.

## Owner decisions to keep

- It is a virtual pub for entertainment: no real beer brands, no urging viewers to drink for real, keep the LED reminders (no drink-driving, no under-18 drinking) and the occasional reminder lines.
- Gifts only get thanks and a virtual item; never present them as buying something real.
- Look: realistic painted scene, not cartoon. Name "Nhậu Đêm 134" (number shown like a blue house plate).
